Back Office · Apuestas Retail · UX/UI

Supervisar una operación sin perder el detalle.

Diseñé desde cero un back office para consultar movimientos, apuestas y usuarios distribuidos entre distintos niveles del negocio retail. La propuesta debía facilitar tanto una revisión general como la búsqueda puntual de un registro, una jugada o un usuario.

Rol UX/UI Designer
Producto Back Office
Alcance Diseño desde cero
Plataforma Web · Desktop
01 · Operación

Una red distribuida genera muchas preguntas.

La supervisión no ocurre sobre un único punto de venta. El usuario administrativo necesita desplazarse entre diferentes niveles, revisar movimientos y reconocer a quién pertenece cada registro.

Cuando esa relación no es evidente, investigar una incidencia o localizar una apuesta específica se vuelve más lento y aumenta el riesgo de interpretar datos pertenecientes a otra parte de la red.

El trabajo UX consistió en relacionar usuario, nivel, movimiento y apuesta para que cada consulta pudiera entenderse desde su origen.

🔒
Confidencialidad

Proyecto desarrollado bajo confidencialidad.

La plataforma contiene información vinculada a procesos internos y a la operación de apuestas retail.

Por este motivo, algunas pantallas, datos y flujos específicos no pueden mostrarse públicamente. El case study se concentra en el problema de producto y las decisiones UX/UI sin revelar información sensible.

02 · El reto

Encontrar lo importante entre cientos de registros.

El volumen de datos era solo una parte del problema. También era necesario facilitar búsquedas recurrentes, desplazarse entre niveles y diferenciar con precisión datos, estados y acciones.

01

Alta cantidad de registros

Movimientos y apuestas necesitaban poder localizarse sin recorrer filas manualmente.

02

Navegación entre niveles

Al profundizar en la red debía quedar claro qué usuario, terminal o nivel se estaba administrando.

03

Consultas recurrentes

Fechas, estados y otros criterios necesitaban filtros predecibles y fáciles de reutilizar.

03 · Arquitectura

Tres tareas, tres módulos principales.

La plataforma se organizó según las tareas que el equipo administrativo necesita resolver con mayor frecuencia.

MÓDULO 01

Estado de caja

Consulta de movimientos y actividad operativa asociados al nivel seleccionado.

MÓDULO 02

Historial de apuestas

Búsqueda y revisión de jugadas mediante filtros que reducen el volumen de registros a analizar.

MÓDULO 03

Gestión de usuarios

Administración de usuarios y acceso a los diferentes niveles que conforman la red retail.

04 · Sistema

Aprender una vez, operar en todo el back office.

Tablas, filtros, estados y acciones siguen una lógica común entre módulos para evitar que cada área se comporte como una herramienta diferente.

Una vez aprendido el comportamiento de una tabla o un filtro, ese conocimiento puede reutilizarse al consultar apuestas, movimientos o usuarios.

UBICACIÓN

Saber dónde se opera

El nivel seleccionado se identifica antes de presentar sus registros.

CONSULTA

Encontrar antes de revisar

Búsqueda y filtrado reducen la cantidad de datos que necesitan analizarse.

ACCIÓN

Diferenciar qué se puede modificar

Estados y controles utilizan tratamientos distintos para reducir ambigüedades.

🔒 Interfaz protegida por confidencialidad

Algunas vistas operativas no pueden mostrarse públicamente.

05 · Decisiones UX/UI

Diseñar para consultar y verificar.

Las principales decisiones responden a tareas administrativas: encontrar un registro, comprobar su procedencia y actuar sobre él con la menor ambigüedad posible.

01

Ubicación operativa

Indicar claramente qué parte de la red se está revisando antes de mostrar sus datos.

02

Tablas escaneables

Columnas y alineaciones ayudan a localizar valores concretos sin leer cada registro completo.

03

Filtros prioritarios

La búsqueda se trata como una tarea principal porque gran parte del trabajo comienza encontrando una operación específica.

04

Estados diferenciados

Datos, estados y acciones utilizan niveles visuales distintos para disminuir errores de interpretación.

05

Patrones repetibles

Los mismos comportamientos se reutilizan entre módulos para reducir el esfuerzo de aprendizaje.

06

Base escalable

Los componentes admiten nuevos estados y funcionalidades sin reconstruir cada pantalla.

06 · Resultado

Una operación más fácil de consultar.

La propuesta reúne movimientos, apuestas y usuarios dentro de un sistema administrativo común.

En lugar de simplificar eliminando datos, el diseño facilita encontrar, relacionar y verificar la información necesaria según el nivel que se está supervisando.

02 Navegación preparada para diferentes niveles de la red.
